# 关机画面与正常关机

2026-10-21已烧录并完成用户实机确认：USB与纯电池供电均可正常关机、保持画面，再用PWR开机恢复仪表盘及BLE。详见 `3Inch7EPaper/artifacts/morning-validation.json`。

## 画面

白底细圆角边框，睡着的墨水屏与月牙线稿，64px原生字形“已关机”，小字“同步与采样已停止”，底部提示长按PWR开机、USB供电可重新上电。横竖屏各自排版，保持关机时的屏幕方向。关机页不保留额度、传感器读数或运行时钟，避免把残留数据误认为仍在更新。

预览：`3Inch7EPaper/artifacts/shutdown-0.png`、`3Inch7EPaper/artifacts/shutdown-90.png`。这是本地绘图代码渲染，未拍摄实屏。画面刷新完成后，屏幕休眠并切断ALDO3供电，图像依靠墨水屏本身保持。

## 手势与顺序

- PWR按1.2秒至不足3秒后松手：暂停/恢复刷新，改为松手时执行，避免准备关机时先触发暂停。
- PWR按约3秒后松手：正常关机。3秒触发一次，不附带暂停、单击或重复关机事件；BOOT的3秒配网保持不变。PMU读键失败时清除PWR手势状态，不从过期的按下状态推断关机。
- PWR持续8秒：保留原有PMU硬件强制关机。正常关机请3秒后松手，让固件完成保存与刷屏；持续强制断电可能早于这些操作完成。

正常路径为：环境日志任务尝试保存待写记录并关闭文件→日志暂停→网络任务停止BLE/网页/Wi-Fi并暂停→全刷“已关机”并等待BUSY完成→屏幕休眠、关闭屏幕电源→请求PMU关机。如果USB电源路径仍维持CPU供电，则进入无定时唤醒的Deep-sleep兜底，停止采样、同步和重绘，不能在“已关机”画面后继续后台运行。

日志准备等待上限2秒，网络准备3秒。准备超时、网络未能停妥或关机帧传输失败时，取消软件关机并恢复任务，不请求PMU断电；尝试全刷“关机未完成”，随后恢复正常仪表盘。未插卡时允许正常关机，未写入SD的RAM采样不能保证断电保存，画面不声称全部数据已保存。

PMU关机只在ID符合当前板的`0x4A`检查后，读改写`REG10[0]=1`，不修改充电参数或eFuse。依据微雪提供的[TG28数据手册](https://files.waveshare.com/wiki/common/TG28_Datasheet_V1.0_en.pdf) 6.5.4.3及REG10表（第16、25–26页），与上游`XPowersAXP2101::shutdown()`一致。Deep-sleep前先关闭无线的顺序依据本机ESP-IDF v6.1 `docs/en/api-reference/system/sleep_modes.rst`；官方Protocomm NimBLE停止路径负责`nimble_port_stop/deinit`。

## 边界与实机验证

拔线、拔电池、低压或强制硬件断电发生后，CPU没有电量继续画新图，因此不能保证留下关机页；也不把最后一次“运行中”标记当成可靠的断电检测。只有正常关机流程完成后，才保证软件已发送关机画面。

离线已通过：关机顺序与SD/网络/显示失败取消测试，PWR暂停/关机阈值、互斥/防重复/再次尝试测试，8组关机/失败画面与四方向边界检查（ASan/UBSan），横竖屏预览检查，固件编译。没有操作已拔走的硬件。

2026-10-21实测：app-only升级保留NVS/绑定；用户确认“出现‘已关机’，画面保持”，PWR约1秒后可重新开机。日志记录SD quiescent stored=455 unsaved=0、网络停止和USB断开；再开机恢复455条并继续写入，BLE自动重连。用户随后确认“电池供电关机、开机都正常，已插回USB”。这验证实际使用流程；没有测量关机电流，不能单凭USB断开区分PMU切电与Deep-sleep兜底，也没有做强制掉电故障测试。
